## S1. 관심종목 목록 (홈)

**화면 Title** — "관심종목"

### 목록 구성

관심종목과 보유종목을 **한 목록에 섞지 않습니다.** 두 섹션으로 나눕니다.

```
[ 관심종목 ]        ← 아직 사지 않은 것. 이 제품의 주 무대
  종목 카드 …
  + 종목 추가

[ 보유중 ]          ← 이미 산 것. 전제 추적은 계속됨
  종목 카드 …
```

데이터 모델의 `watchlist_items.status`(`watching` / `bought`)로 갈립니다.

### 종목 카드

| 위치 | 요소 |
|---|---|
| 좌 | 종목명, 종목코드 |
| 우 | 현재가, 등락률 |
| 최우측 | `구매` 버튼 (관심종목 섹션에만) |

- `구매` 버튼 → S4 (주문 전 확인). **근거가 없는 종목은 S4를 열지 않고** 그 자리에서 안내 토스트만 띄웁니다 (S4 참조)
- 그 외 영역 탭 → S5 (관심종목 상세)

**보유중 카드에 `구매`가 없는 것은 의도입니다** — 버그가 아닙니다. 목록의 `구매`는 "아직 안 산 것을 사러 가는" 진입점이고, 보유중에 필요한 것은 추가 매수냐 매도냐라는 **판단**이라 상세(S5)에 둡니다. 

### 상태 배지

| 배지 | 조건 |
|---|---|
| `근거 없음` | 근거를 쓰지 않고 담은 종목 |
| `유지 중` | 저장된 전제가 모두 유효 |
| `달라짐` | 전제 중 하나 이상이 깨짐 |



### 변동 요약

`달라짐` 종목 수가 **0에서 N으로 올라가는 순간**, 화면 하단 중앙에 4초짜리 토스트로 지나갑니다.

> "2개 종목에서 달라진 점이 있어요"

**탭할 수 없습니다.** 데모 시점과 무관하게 같은 규칙으로 동작하며(같은 사실을 시점에 따라 다른 모양으로 말하면 사용자가 배울 수 없는 규칙이 생깁니다), 토글 On·담기 직후 복귀·최초 로딩 완료가 모두 이 한 규칙에 덮입니다. 시세가 늦게 도착해 개수가 2→3처럼 올라가는 재발화는 막습니다.



### 데모 상태

`3개월 후 보기` 토글을 누르면 S1이 눈에 띄게 달라져야 합니다. 사용자가 이 제품의 가치를 30초 안에 체감하는 지점이 여기입니다.

| | 현재 | 3개월 후 |
|---|---|---|
| 변동 요약 | 없음 | **"2개 종목에서 달라진 점이 있어요"** (토스트) |
| 시드 A 배지 | `유지 중` | `달라짐` |
| 시드 B 배지 | `유지 중` | `달라짐` (전제 3개 중 1개) |
| 시드 C | `근거 없음` | `근거 없음` (변화 없음) |
| 가격 | 실시간 | 시나리오 값 |

**배지·배너는 가격과 반드시 함께 갱신됩니다.** 데모 시점은 표시 옵션이 아니라 전제 판정의 입력이라(기술스펙 6·7장), 토글 한 번에 이 표의 다섯 행이 동시에 바뀌어야 합니다. 가격만 미래로 바뀌고 배지가 `유지 중`에 남아 있으면 이 화면은 클라이맥스가 아니라 버그로 보입니다.



### 기타

- 화면 상단: 데모 시나리오 토글 `[데모용] 3개월 후 보기`. `데모용` 뱃지는 **On/Off와 무관하게 상시** 노출합니다 — 임시로 덧댄 장치라는 사실이 없으면 원래 있던 기능처럼 읽히고, 그 오해는 Off 상태에서 라벨만 보일 때 생깁니다(#103).
- 데모 안내문구(토글 On일 때만): "서비스 컨셉 데모를 위해 3개월 후 상황을 가정한 값을 보여드립니다". 이 자리의 목적은 "이건 진짜가 아니다"를 짧게 말하는 것이라, 실제로는 시드 종목만 fixture 시세로 갈아탄다는 사실(사용자가 담은 종목은 미래 시점에도 실시간 시세)까지는 말하지 않습니다.
- 빈 상태 문구: "관심 가는 종목을 담아보세요. 왜 담았는지 같이 적어두면 나중에 도움이 됩니다."
- 목록 하단 full-width 버튼: `+ 종목 추가` → S1.5. 앞의 `+`는 문자가 아니라 **아이콘**입니다 — 같은 기호는 앱 안에서 한 모양이어야 합니다.
- 담기·제외 후 이 화면으로 돌아왔을 때 **목록은 이미 바뀌어 있어야 합니다.** 방금 담은 카드가 늦게 나타나거나 방금 뺀 카드가 남아 있으면 안 되고, 건드리지 않은 카드의 가격·배지가 함께 깜빡여서도 안 됩니다(ADR-0010).

## S2. 근거 입력 (3 step)

### 헤더

Title은 **종목명**을 노출합니다.

### 진행 표시

헤더 아래에 **3분절 막대** 하나. 채워진 칸 수가 현재 Step입니다. `1/3` 같은 숫자 문구는 두지 않습니다 — 연속 막대였을 때 총 단계 수를 말해줄 방법이 없어 텍스트가 필요했지만, 칸을 나누면 막대가 비율과 개수를 함께 말합니다. 한 정보를 두 줄에 나눠 싣던 것이 문제였습니다.

Step 3에서는 막대가 가득 찹니다. `이대로 담기`를 누르기 전이지만, 막대가 세는 것은 **남은 입력량**이지 저장 여부가 아닙니다.

### Step 1 — 카테고리 선택 (단일 선택)

> 헤드라인: "왜 이 종목에 관심이 있으세요?"
> 보조문구: "이유를 알려주시면 AI가 놓친 점은 없는지 함께 짚어드려요."

처음 온 사용자는 이 질문에 답하면 무엇을 얻는지 모른 채 카테고리를 고릅니다(UT). 보조문구가 대가를 말합니다 — 다만 제품이 S3에서 실제로 하는 일(반론 + 열린 질문)까지만 약속하고, "함께 생각해드려요" 같은 대화형 코칭은 약속하지 않습니다.

```
실적·성장   |  저평가      |  테마·모멘텀  |  배당
기술적 신호  |  누가 추천해서 |  그냥 느낌
```

하단 CTA: `다음`. 그 위에 작은 underline text 버튼으로 `건너뛰기` — 근거 없이 종목만 담고 S1으로 갑니다(시드 C·LG에너지솔루션과 같은 `근거 없음` 상태). 이미 담긴 종목으로 들어온 경우(S5 `생각 업데이트 하기`)에는 렌더하지 않습니다.

"누가 추천해서", "그냥 느낌"은 반드시 남깁니다. 고르는 순간 자각이 일어나므로, AI가 입을 열기 전에 절반은 작동합니다.

### Step 2 — 후속 질문 (2~3개)

카테고리별 질문은 **6장에 전부 정의**되어 있습니다. 사전 정의된 질문을 기본으로 하고, 답변 내용에 따라 LLM이 한 개까지 추가 질문을 만들 수 있습니다.

- 모든 질문은 선택지 + `직접 입력` 제공
- 선택지 칩은 **토글**입니다. 고른 칩을 다시 누르면 해제됩니다.
- **답하지 않은 질문은 무선택으로 표현합니다.** 질문 옆에 별도 `건너뛰기` 버튼을 두지 않습니다 — 해제가 막혀 있어 생겼던 우회로였고, Step 1의 `건너뛰기`(근거 없이 담기)와 같은 말이 한 화면에서 두 뜻을 갖게 됩니다. 무선택 문항은 저장될 때 `skipped`로 채워지므로 "무엇을 비워뒀는지"는 그대로 남습니다.
- 하단 `다음`은 **최소 한 문항**을 답해야 열립니다. 아무것도 쓰지 않겠다는 선택은 Step 1의 `건너뛰기`가 받습니다.

### 마지막 질문은 값을 받습니다 — 빠뜨리지 말 것

각 카테고리의 마지막 질문은 **관측 가능한 값**(목표가, 손절가, 기간)을 받도록 설계했습니다. 이 값이 있어야 전제가 자동 판정 대상이 됩니다.

예를 들어 저평가 카테고리는 질문이 셋입니다.

| Q1 | 무엇 대비 싸다고 보세요? |
| Q2 | 어느 지표로 보셨어요? |
| **Q3** | **어디까지 오르면 제값이라고 보세요? (목표가 입력)** |

Q3이 빠지면 S3에서 "목표가 210,000원" 전제를 만들 근거가 없습니다. 앞의 두 질문만으로는 `price` 전제가 도출되지 않습니다.

3~4개 질문이 한 화면에 다 들어가지 않으면 스크롤로 처리하고, 값을 받는 마지막 질문을 잘라내지는 마세요.

### Step 3 — 자유 서술 (선택, 200자)

> "덧붙이고 싶은 생각이 있다면 적어주세요. (건너뛰어도 됩니다)"

`이대로 담기` CTA.

## S3. AI 검증 결과

### 화면은 두 국면입니다

세 덩어리(반대 시각 · 확인해볼 질문 · 전제)를 나란히 세우지 않고 **두 국면**으로 접습니다. 국면 1은 지금 `다시 쓰기`냐 `이대로 담기`냐를 판단하게 하는 것, 국면 2는 담은 뒤에 남는 것입니다.

```
이런 점은 어떻게 보세요?          ← 국면 1 제목
  • 반대 시각                     불릿, 카드 없음
  확인해볼 질문                   국면 1 안의 라벨
  • 질문                          불릿, 카드 없음

앞으로 이걸 지켜보면 됩니다        ← 국면 2 제목
  ┌──────────────────┐
  │ 전제 행 + 배지     │           섹션 카드 하나
  └──────────────────┘
```

**두 국면 제목은 대등합니다.** 예전에는 "이런 점은 어떻게 보세요?"만 헤드라인이고 나머지 둘은 작은 회색 소제목이라, 같은 층의 것 셋이 세 가지 크기로 서 있었습니다. 위계는 국면 제목 → 섹션 라벨 → 행, 세 층입니다.

**국면 사이를 가르는 것은 간격뿐입니다.** 구분선도 배경 톤 분리도 쓰지 않습니다(CONTEXT.md `섹션 카드`). 국면 사이 간격은 국면 안 간격의 두 배입니다.

**카드는 국면 2에만 씁니다.** 국면 1을 카드로 감싸면 그 사이에 낀 `확인해볼 질문` 라벨이 어느 쪽에도 속하지 않는 것처럼 보입니다. 카드가 화면에 하나뿐일 때 카드는 "앞으로 남는 것"을 가리키는 표식이 됩니다.

**반대 시각과 확인해볼 질문은 같은 불릿 문법을 씁니다.** 둘을 가르는 것은 표시법이 아니라 사이에 놓인 라벨입니다. 두 필드는 서로 다른 일을 하며(`프롬프트 명세.md` 641·711행 — 카테고리에 따라 무게가 반박이 아니라 질문에 실립니다), 그래서 질문을 회색으로 깔아 부속물처럼 두지 않습니다.

**`severity`는 화면에 노출하지 않고 정렬에만 씁니다.** `major`가 위로 올라갑니다. "major"는 사용자에게 개념어이고(0-1), 배지로 만들면 전제의 `자동 확인`/`직접 확인 필요`와 한 화면에서 네 종류 배지가 경쟁합니다.

**`basis`는 본문과 같은 크기(`text-sm`)입니다.** 숫자가 들어오는 유일한 자리라 가장 작은 글씨에 둘 이유가 없고, 무게 분리는 크기가 아니라 색이 맡습니다. 이 화면의 글자 크기는 둘뿐입니다.

### 분기

**반박할 지점이 있을 때** (`is_challengeable = true`)

> 국면 1 제목: "이런 점은 어떻게 보세요?"

- 반대 시각 2~3개 (각각 근거 표시)
- `확인해볼 질문` 라벨 + 질문

**반박할 지점이 약할 때** (`is_challengeable = false`)

> 국면 1 제목: "생각이 구체적이네요. 이것만 확인해보세요."

- 반대 시각 목록을 **렌더하지 않습니다**
- `확인해볼 질문` 라벨도 **함께 뺍니다** — 국면 1에 남는 것이 질문뿐이라 제목이 곧 라벨입니다
- `is_challengeable`이 false여도 `open_questions`는 비지 않습니다(`프롬프트 명세.md` 564행)

옛 문구 "생각이 구체적이네요. 대신 이건 지켜볼 만합니다."의 뒷절은 국면 2를 가리킵니다. 바로 아래에 "앞으로 이걸 지켜보면 됩니다"가 또 나오므로 두 제목이 같은 말을 하게 되어, 뒷절을 질문 쪽으로 돌렸습니다.

### 전제 섹션 (국면 2)

> "앞으로 이걸 지켜보면 됩니다"

각 전제에 배지: `자동 확인` / `직접 확인 필요`

**두 배지가 함께 보이는 화면이 반드시 필요합니다.**

```
PER 15배 이하 유지            [자동 확인]
목표가 210,000원              [자동 확인]
경쟁사가 이 시장에 들어오지 않는다   [직접 확인 필요]  3개월 뒤 알려드릴게요
```

자동 판정이 안 되는 전제가 있다는 사실을 감추지 않는 것이 이 제품의 설계 원칙입니다(기술스펙 C-8). 그런데 `자동 확인`만 나오는 화면만 있으면 그 원칙이 화면에 존재하지 않는 것과 같습니다.

저평가 카테고리는 자동 판정이 잘 되는 편이라 예시로 쓰면 이 배지가 안 나옵니다. **S3 시안 중 하나에는 `qualitative` 전제를 섞어주세요.** 데모 시드 종목 B가 그 역할을 맡습니다.

### 액션

`다시 쓰기` (→ S2 Step 1) / `이대로 담기` (→ S1, 방금 담은 카드 하이라이트)

## S4. 주문 전 확인

`구매` 버튼을 누르면 bottom sheet가 올라옵니다.

**`데모 시점`을 읽지만 선언하지는 않습니다.** S5와 달리 여기에는 `3개월 후 보기가 켜져 있어요`가 뜨지 않습니다 — 시트는 스스로 임시인 표면이라, 시점 선언은 뒤에 선 화면의 몫입니다. 전체 페이지 변종에 URL로 직접 닿는 것은 비정상 경로라 대응하지 않습니다. 규율 자체는 CONTEXT.md `데모 시점`에 있습니다 (#134).

**이 시트가 확인시키는 것은 담을 때 입력한 전제뿐입니다.** 수량 조절도 합계 금액도 두지 않습니다 — 뒤에 실제 주문 화면이 있다고 전제하고, 얼마나 살지는 거기서 정합니다. 남는 것은 근거·전제와, 그것을 읽는 문맥인 종목명·현재가까지입니다 (#143).

### 구성

**전제가 유지될 때**

> "이렇게 생각하셨어요"

**시점은 말하지 않습니다.** 원래 문구는 "3주 전에 이렇게 생각하셨어요"였습니다. 그런데 데모에는 시계가 없습니다 — `3개월 후` 토글은 시세 변종일 뿐이고 `thesis.createdAt`은 그대로라, 어떤 기준으로 상대 시점을 계산해도 화면의 시제와 어긋납니다. `3개월 후`를 보며 미래 시세로 전제가 깨진 화면에서 "10주 전에 이렇게 생각하셨어요"라고 말하면 두 시제가 서로를 부정합니다.

데모 시점을 "가정된 현재"로 승격해 계산을 맞추는 길도 있었지만, 문구 하나를 위해 `DemoScenario`의 의미를 넓히고 S5가 이미 같은 이유로 내려둔 결정(`stock-detail-view.tsx`: "오늘" 행의 날짜 칸을 비운다)까지 뒤집게 됩니다. 작성 시점이 궁금한 사용자에게는 S5가 이미 절대 날짜로 말해줍니다 (#141).

- 근거 요약 (카테고리 + 핵심 답변)
- `전제 상태 · [유지]`
- 종목명 + 현재가
- 액션: `취소` / `구매`

판정이 불가능할 때(시세 조회 실패 / 읽을 수 없는 전제)도 이 골격입니다. 배지가 `확인 불가`가 되고 그 아래 원인을 가르는 한 줄이 붙습니다 — 두 원인에 같은 문구를 쓰지 않는 이유는 S1과 같습니다(#102).

**전제가 달라졌을 때 — 근거 요약을 대체합니다**

> "담으실 때와 달라진 게 있어요"

- **깨진 전제를 전부** 세웁니다 (전제 문장 + `지금은 {관측값}`)
- `전제 상태 · [달라짐]` 배지 행은 **그리지 않습니다**
- `생각이 바뀌셨나요?` 링크
- 종목명 + 현재가
- 액션: `취소` / `구매`

매수 직전에 필요한 정보는 "저평가라고 생각했다"가 아니라 "PER 15배가 지금 22배다"입니다. 근거 요약(카테고리 라벨 + 자유 서술)을 먼저 세우면 틀어진 사실이 그 뒤에 놓이고, 사용자는 옛 생각을 읽은 뒤에야 무엇이 깨졌는지를 배지 하나로 짐작하게 됩니다.

**하나만 고르지 않습니다** — 어느 하나를 고르면 그 선정 기준("첫 번째"?)이 화면에 설명되지 않는 규칙으로 남습니다. 배지 행을 함께 걷는 이유도 같은 종류입니다: 깨진 전제가 눈앞에 펼쳐져 있는데 배지가 같은 말을 한 번 더 합니다.

**근거가 없을 때 — bottom sheet를 띄우지 않습니다**

버튼 자리에서 바로 **"프로토타입에서는 구매를 지원하지 않아요"** 토스트를 띄웁니다. 되비출 근거가 없으니 시트가 종목명과 현재가만 든 채로 뜨고, 그것은 이 화면의 존재 이유가 없다는 뜻입니다.

**단, `order_events`는 그대로 남깁니다** — 화면을 건너뛰는 것과 사건을 안 남기는 것은 별개입니다. "근거 없이 구매를 눌렀다"는 이 제품이 가장 알고 싶어 하는 대조군이라, 시트가 없어도 `proceed`(`thesis_shown: false`)를 남깁니다.

### `유지`일 때도 시트는 뜹니다

수량이 빠지고 나면 `유지` 상태의 시트는 마찰 없는 추가 탭 한 번입니다. 그래도 남깁니다 — `달라짐`일 때만 띄우면 데모 시드가 대부분 `유지`라 시연 중 S4가 거의 열리지 않고, "사기 전에 자기 근거를 한 번 본다"는 이 제품의 주장이 화면으로 증명되지 않습니다. 아래 조건부 노출 표도 "모두 유지 = 링크 없음"이지 "시트 없음"이 아닙니다.

### 주문 실행은 프로토타입 범위 밖입니다

`구매`를 눌러도 실제 주문은 나가지 않습니다 (`trade-client.ts`에 주문 메서드가 없습니다). 대신 **"프로토타입에서는 구매를 지원하지 않아요"** 토스트를 띄우고 시트는 열린 채로 둡니다 — 홈으로 돌려보내면 아무 일도 없었는데 화면이 체결된 척을 합니다.

**버튼을 `disabled`로 두지 않습니다.** 데모에서 "이 제품은 매수를 안 한다"로 읽혀 ADR-0009의 논지를 화면이 스스로 부정합니다. 거짓말이 일어나는 지점은 "실제로 주문이 나가는 순간" 딱 한 곳이고, 그 앞의 화면 전환은 전부 진짜입니다.

**`order_events`는 그대로 남깁니다.** 아래 기록 표는 토스트 여부와 무관하게 그대로 지켜집니다 — `proceed`가 안 남으면 "근거를 보고도 그대로 샀다"는 대조군이 통째로 사라집니다.

### 기록

`취소`, `구매`, `시트 닫기(외부 탭)` **모든 분기에서** `order_events`를 남깁니다.

| action | 조건 |
|---|---|
| `proceed` | 구매 (시트를 건너뛴 경로 포함) |
| `cancel` | 취소 또는 시트 닫기 |
| `update_thesis` | 근거를 다시 쓰러 이동 |

**`adjust`는 더 이상 발생하지 않습니다.** 수량 입력이 이 화면에 있던 이유는 핵심 지표 "근거를 본 뒤 수량을 조정했는가"(가설 2)였지만, 실제 주문이 나가지 않는 이상 `1`에서 `+`를 몇 번 눌렀는지는 진짜 행동이 아니라 시트 안의 손장난이라 가설을 검증하지 못합니다. `initial_qty` / `final_qty`는 늘 `1`로 채웁니다 — **컬럼과 마이그레이션은 그대로 둡니다.** 죽은 지표 하나 때문에 컬럼을 떨어뜨리면 되돌리는 비용이 지우는 비용보다 큽니다.

### 근거를 갱신하는 경로

`취소` / `구매` 두 버튼만으로는 **근거를 보고 생각이 바뀐 사용자가 갈 곳이 없습니다.** 취소하면 그냥 사라지고 근거는 옛날 상태로 남습니다. 가설 2의 세 가지 행동 변화(수량 조정 / 취소 / 근거 갱신) 중 하나가 측정되지 않습니다.

버튼을 셋으로 늘리면 시트가 무거워지므로 **조건부로 노출**합니다.

| 전제 상태 | 노출 |
|---|---|
| 모두 유지 | 링크 없음. `취소` / `구매`만 |
| 하나 이상 달라짐 | 근거 카드 아래에 **"생각이 바뀌셨나요?"** 링크 → S2 Step 1 |

여기서 읽는 전제 상태는 **시트를 여는 그 시점의 데모 시점 기준으로 계산된 값**입니다(기술스펙 6장). S1이 이전에 남겨둔 결과를 주워 읽지 않습니다 — 그러면 사용자가 `3개월 후`로 보고 있는데 시트만 `현재` 기준 상태를 띄워, 마찰이 필요한 순간에 링크가 조용히 사라집니다.

근거 카드 자체를 탭 가능하게 만들어 S2로 보내도 동일하게 동작합니다. 어느 쪽이든 `update_thesis` 이벤트를 남깁니다.

전제가 달라진 상태에서만 뜨기 때문에, 마찰이 필요한 순간에만 나타나고 평소에는 방해하지 않습니다.

## S5. 관심종목 상세

**헤더** — `←` + Title은 종목명

**`데모 시점`이 `3개월 후`면 타이틀 아래 한 줄이 섭니다** — `3개월 후 보기가 켜져 있어요`(#134). 시점을 말하는 곳이 S1뿐이라, 새로고침이나 링크로 이 화면에 바로 서면 미래 기준으로 계산된 배지를 시점도 모른 채 보게 됩니다. 값은 `localStorage`에 남아 다음 방문까지 살아 있습니다.

문구는 **앱의 상태**를 말하지 이 종목의 값이 가정값이라고는 말하지 않습니다 — `3개월 후`에 fixture 시세로 갈아타는 것은 시드 종목뿐이고 사용자가 담은 종목은 그대로 실시간이라(기술스펙 7장), "이 화면의 값은 가정값입니다"는 비시드 종목에서 거짓이 됩니다. 그렇다고 시드 종목에서만 띄우지도 않습니다 — 침묵의 근거가 화면에 없으면 사용자는 "이 종목은 원래 안 바뀐다"와 "선언이 아직 없다"를 구분할 수 없습니다.

**로딩 헤더에도 같은 줄이 섭니다.** 로딩에 없다가 본문에 나타나면 전환에서 헤더 높이가 뜁니다(#129가 8px 때문에 타이틀 행을 공통 셸로 뽑은 그 종류의 점프입니다). **관심종목에서 찾을 수 없는 화면에는 뜨지 않습니다** — 그 화면의 내용은 "찾을 수 없어요"가 전부라, 없는 종목의 시점을 말하는 꼴이 됩니다. 노출 게이트는 홈 배너와 같이 시점 값 하나이며, 하이드레이션 전 한 프레임의 부재는 홈과 같이 감수합니다.

### 구성

**가격 흐름** — 상태에 따라 기준이 다릅니다

시점을 **행으로 세운 표**입니다. 관심종목이면 두 시점, 보유 종목이면 세 시점입니다.

```
[ 관심종목 ]                          [ 보유중 ]
가격 흐름                             가격 흐름
┌───────────────────────────────┐    ┌───────────────────────────────┐
│ 담은 날  6/18      172,000원  │    │ 담은 날  5/2        82,000원  │
│ 오늘               186,500원  │    │ 매수     5/20       78,900원  │
│ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │    │ 오늘                78,200원  │
│ 담은 날 대비          +8.4%  │    │ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │
└───────────────────────────────┘    │ 담은 날 대비          -4.6%  │
                                     │ 손익                  -0.9%  │
                                     └───────────────────────────────┘
```

**두 기준이 모두 필요한 이유** — 근거가 아직 유효한지는 **담은 날 가격** 기준으로 봐야 하고, 실제 손익은 **매수가** 기준입니다. 담은 시점과 산 시점이 다를 수 있으므로 하나만 보여주면 둘 중 하나를 오해하게 됩니다. 관심종목 상태에서는 아직 매수가가 없으므로 `매수`·`손익` 두 행이 빠집니다.

**표로 세우는 이유**(#127) — 예전에는 `담은 날 172,000원 (6/18) → 현재 186,500원 +8.4%` 한 줄이었는데, 라벨·날짜·가격이 뒤섞여 **세로 스캔선이 없었습니다**. 3열(라벨 · 날짜 · 값)로 세우면 모든 숫자가 오른쪽 한 축에 꽂혀 한눈에 비교됩니다. 날짜를 라벨에 붙이지 않는 것도 같은 이유입니다 — 라벨 길이가 달라도 날짜가 세로로 맞습니다.

**세 번째 시점은 `오늘`이고, 그 행의 날짜 칸은 비어 있습니다**(#132). 예전에는 라벨 `현재` 옆 날짜 칸에 `오늘`을 적었는데, 두 칸이 같은 말을 두 번 해 이 표의 이점인 세로 스캔선 하나를 낭비했습니다. 날짜를 채우지 않는 이유는 **데모에 시계가 없다**는 것입니다 — `3개월 후`는 시세만 바꾼 값이고 담은 날짜는 그대로라, 그 모드의 '오늘'에 해당하는 날짜가 존재하지 않습니다. 없는 값을 지어내느니 칸을 비웁니다.

**`3개월 후` 모드에서도 이 행은 `오늘`이라고 씁니다.** 시뮬레이션은 앱 전체가 하는 것이고 이 화면의 헤더가 위에서 이미 한 번 선언합니다 — 행마다 `3개월 후`를 붙이면 서비스 화면이 자기가 데모라는 것을 매번 실토하는 꼴이 됩니다.

**점선은 실선과 다른 종류의 경계입니다.** 문단 구분이 아니라 "위는 관측된 값, 아래는 그걸로 계산해낸 값"이라는 선이라, 근거 카드가 쓰는 실선을 빌려 쓰지 않습니다.

**보유중의 두 파생값을 한 줄에 나란히 두지 않습니다.** 한 줄에 넣으면 앞쪽 퍼센트가 오른쪽 정렬선 밖으로 벗어나 이 표의 이점이 깨집니다. 두 행으로 세우면 위에서 아래로 `담은 날 → 매수 → 오늘 → 담은 날 대비 → 손익` 순이 되어, 두 파생값이 어느 행에서 왔는지가 순서만으로 드러납니다.

**시세가 없어도 행은 사라지지 않습니다.** 조회 중이면 값 자리에 스켈레톤, 기준 가격이 없으면 `-`입니다. 행을 통째로 지우면 시세가 도착하는 순간 카드 높이가 튑니다.

**내가 쓴 근거**

- 카테고리와 후속 질문 답변
- 자유 서술 (있으면)
- 작성 시점

**전제별 상태**

| 상태 | 표시 |
|---|---|
| 유지 | 기준값과 현재값 |
| 달라짐 | 기준값 → 관측값, 강조 |
| 직접 확인 필요 | 확인 시점 안내 |

> "담으실 때 보신 것과 달라진 게 있어요"
> "PER 15배 이하 → 지금은 21.3배"

### 액션

상태에 따라 갈립니다.

| 자리 | 관심종목 | 보유중 |
|---|---|---|
| body 맨 아래 | `생각 업데이트 하기` \| `근거 적기` | `생각 업데이트 하기` \| `근거 적기` |
| 하단 바 왼쪽 | `관심종목에서 제외` | `판매` |
| 하단 바 오른쪽 | `구매` | `구매` |

**두 상태가 같은 골격을 씁니다.** 근거 갱신은 body 맨 아래, 하단 바는 오른쪽이 언제나 `구매`이고 왼쪽 칸만 갈립니다 — 왼쪽에 오는 것은 그 상태에서만 뜻이 있는 행동입니다. 아직 안 샀으면 담아둔 것을 치우는 일, 이미 샀으면 파는 일입니다.

**근거 갱신을 하단 바에 고정하지 않는 이유**는 그럴 필요가 없기 때문입니다. 앰버라 body 안에서도 충분히 눈에 띄고, 하단 바를 비워둔 만큼을 각 상태의 고유한 행동에 내줄 수 있습니다. 대신 하단 바 버튼(48px 전체폭)과 치수를 맞추지 않습니다 — body 안의 내용물이므로 40px에 라벨 폭 + 좌우 패딩, 중앙 정렬로 두어 바가 하나 더 있는 것처럼 읽히지 않게 합니다. 근거가 없는 종목이면 라벨이 `근거 적기`가 되는데, 그때는 바로 위의 "아직 왜 담았는지 적어두지 않았어요" 빈 카드가 이 버튼을 가리킵니다.

**보유중에 `판매` / `구매`를 두는 이유**는 ADR-0009에 있습니다. 요지는 **대칭**입니다 — 단독 `매도 검토`는 제품이 방향을 고르는 것이고, 양방향을 같은 폭·같은 위계로 나란히 두는 것은 방향을 고르지 않습니다. 보유한 종목이니 두 길을 동등하게 열어둘 뿐입니다. 그래서 **대칭을 시각적으로 깨지 않습니다** — 판매만 약하게 그리거나 `disabled`로 두면 제품이 매수 쪽으로 기울었다는 신호가 됩니다.

**두 버튼 모두 뒤에 시트가 없습니다.** 버튼 자리에서 바로 **"프로토타입에서는 판매를/구매를 지원하지 않아요"** 토스트를 띄웁니다.

`구매`가 S4를 열지 않는 이유는 **이 화면이 이미 S4의 내용이기 때문입니다** — 근거와 전제별 상태가 눈앞에 펼쳐져 있는데 시트를 덧대면 같은 것을 한 겹 더 보여주는 탭 한 번이 됩니다. 게다가 `판매`만 토스트고 `구매`만 시트인 비대칭은 위에서 지키기로 한 대칭을 화면 뒤에서 깨는 것이라, 제품이 매수 쪽으로 기울었다는 신호가 됩니다(ADR-0009).

S1 카드의 `구매`는 관심종목 섹션에만 붙으므로, **보유중 종목이 S4에 닿는 경로는 없습니다.** 의도한 결과입니다 — 추가 매수 직전에 되비출 근거는 이 화면이 이미 다 보여주고 있습니다 (#143).

`관심종목에서 제외`는 매매가 아니라 **정리 행위**라 outline으로 물러섭니다 — 빨간 `구매`와 같은 무게로 서지 않습니다. 3버튼 바를 쓰지 않는 한 폭은 문제되지 않습니다(2버튼이면 버튼당 181px, 이 라벨은 ~150px).

**해제에는 확인을 세웁니다.** `removeWatchlistItem`은 소프트 삭제지만 **다시 담는 경로가 그 행을 되살리지 않습니다** — 근거는 사라지고 담은 날 가격도 오늘로 새로 시작합니다. 버튼이 어디에 놓이든 이 사실은 그대로이고, 눈에 띄는 `구매` 바로 옆이라 오탭 비용이 오히려 더 큽니다.

> "관심종목에서 뺄까요? / 빼면 적어두신 근거도 함께 사라져요. 다시 담아도 되돌아오지 않아요."

**보유중에도 `생각 업데이트 하기`를 엽니다.** 전제 추적이 계속되는데 근거를 고칠 길이 없던 구멍을 막습니다.

## 6. 카테고리별 후속 질문 정의

Step 2에서 사용합니다. 각 카테고리마다 고정 질문 2~3개를 두고, LLM은 답변에 따라 최대 1개까지만 추가 질문을 만듭니다.

**설계 원칙**

- 모든 질문에 정직한 회피 선택지를 넣습니다 ("생각 안 해봤어요", "잘 모르겠어요"). 고르는 순간 자각이 일어납니다
- 마지막 질문은 가능하면 **관측 가능한 값**을 받습니다. 그래야 전제가 자동 판정 대상이 됩니다
- "누가 추천해서"와 "그냥 느낌"은 전제를 뽑기 어렵습니다. 대신 **자각과 금액 통제**로 방향을 돌립니다

---

### 1. 실적·성장

| # | 질문 | 선택지 |
|---|---|---|
| Q1 | 어떤 성장을 기대하세요? | 매출 성장 / 이익 개선 / 신사업·신제품 / 점유율 확대 / 직접 입력 |
| Q2 | 언제쯤 확인할 수 있을까요? | 다음 분기 / 6개월 / 1년 / 정해두지 않음 |
| Q3 | 기대만큼 안 나오면 어떻게 하실 건가요? | 팔겠다 / 더 기다린다 / 생각 안 해봤어요 |

**도출 전제** — `fundamental`(직접 확인) + Q2 기간으로 리마인드 설정

---

### 2. 저평가

| # | 질문 | 선택지 |
|---|---|---|
| Q1 | 무엇 대비 싸다고 보세요? | 동종업계 / 과거 이 종목의 밸류에이션 / 자산가치 / 직접 입력 |
| Q2 | 어느 지표로 보셨어요? | PER / PBR / 주가 자체 / 잘 모르겠어요 |
| Q3 | 어디까지 오르면 제값이라고 보세요? | 목표가 직접 입력 / 정하지 않음 |

**도출 전제** — `valuation`(자동) + `price`(자동). **자동 판정이 가장 잘 되는 카테고리**입니다. 데모 시드 종목 B를 여기에 배치하면 좋습니다.

---

### 3. 테마·모멘텀

| # | 질문 | 선택지 |
|---|---|---|
| Q1 | 어떤 테마인가요? | 직접 입력 (짧게) |
| Q2 | 이 흐름이 얼마나 갈 거라고 보세요? | 몇 주 / 몇 달 / 1년 이상 / 모르겠어요 |
| Q3 | 테마가 식었다는 건 뭘 보면 알까요? | 거래량 감소 / 관련 뉴스가 줄어듦 / 주가 하락 / 생각 안 해봤어요 |

**도출 전제** — `price`(자동) + `qualitative`. Q2 기간이 지나면 리마인드.

> 테마는 유통기한이 있습니다. Q2를 반드시 묻는 이유는, 기한을 정하지 않은 테마 투자가 가장 오래 물리기 때문입니다.

---

### 4. 배당

| # | 질문 | 선택지 |
|---|---|---|
| Q1 | 지금 배당수익률은 확인하셨어요? | 네, 충분합니다 / 네, 아쉽지만 성장도 기대 / 아직 안 봤어요 |
| Q2 | 배당이 줄어도 계속 들고 계실 건가요? | 아니요, 팔겠습니다 / 네, 다른 이유도 있어요 / 생각 안 해봤어요 |
| Q3 | 얼마나 오래 보실 생각이세요? | 1년 / 3년 / 그 이상 / 정하지 않음 |

**도출 전제** — `fundamental`(배당 유지, 직접 확인) + `qualitative`

---

### 5. 기술적 신호

| # | 질문 | 선택지 |
|---|---|---|
| Q1 | 어떤 신호를 보셨어요? | 이동평균 돌파 / 거래량 급증 / 지지선 반등 / 차트 패턴 / 직접 입력 |
| Q2 | 신호가 틀렸다면 어디서 정리하실 건가요? | 손절가 직접 입력 / -10% / -20% / 정하지 않음 |
| Q3 | 목표가는 정하셨어요? | 목표가 직접 입력 / 정하지 않음 |

**도출 전제** — `price`(자동). Q2·Q3이 모두 가격이라 판정이 명확합니다.

> Q2가 이 카테고리의 핵심입니다. 기술적 신호로 진입하면서 손절선을 정하지 않는 것이 가장 흔한 실패이고, 묻는 것만으로 효과가 있습니다.

---

### 6. 누가 추천해서

| # | 질문 | 선택지 |
|---|---|---|
| Q1 | 어디서 보셨어요? | 유튜브·방송 / 커뮤니티 / 지인 / 증권사 리포트 / 기사 |
| Q2 | 그분이 왜 좋다고 하던가요? | 직접 입력 (짧게) |
| Q3 | 그 이유를 직접 확인해보셨어요? | 네 / 일부만 / 아니요 |

**도출 전제** — 대부분 `qualitative`. **Q3이 이 카테고리의 목적**입니다.

> 압박이 목표가 아니라 자각이 목표입니다. Q3에서 "아니요"를 고르면, AI는 반박하는 대신 "무엇을 확인해보면 좋을지"를 목록으로 제시합니다.

---

### 7. 그냥 느낌

| # | 질문 | 선택지 |
|---|---|---|
| Q1 | 어떤 느낌이세요? | 앞으로 잘 될 것 같다 / 요즘 자주 보인다 / 써보니 좋다 / 싸 보인다 |
| Q2 | 얼마나 넣으실 생각이세요? | 소액으로 / 평소만큼 / 평소보다 크게 |
| Q3 | 틀려도 괜찮은 금액인가요? | 네 / 아니요 / 생각 안 해봤어요 |

**도출 전제** — 거의 없음. 기간 리마인드만 설정.

> 근거가 없으면 전제를 만들 수 없습니다. 억지로 만들면 거짓 전제가 됩니다.
> 대신 **금액 통제**로 방향을 돌립니다. "근거가 뚜렷하지 않을 때는 크기를 줄이는 게 안전하다"는 것은 종목 추천이 아니라 리스크 관리라서 규제 경계에도 안전합니다.
> Q2에서 "평소보다 크게" + Q3에서 "생각 안 해봤어요"의 조합이 나오면 AI가 가장 강하게 짚어야 할 지점입니다.

## 7. 변경 이력

**v3** — 불필요하게 많은 정보/outdate된 정보는 삭제.

**v2** — 와이어프레임 1차 검토 반영

- S1: 관심종목/보유중 분리, 변동 요약, 3상태 배지, '3개월 후' 상태 정의
- S1.5: 종목 검색 화면 신설
- S2: 헤더를 종목명으로, 진행 표시, 건너뛰기, 마지막 질문에서 값 수집 강조
- S3: `직접 확인 필요` 배지가 보이는 화면 필수화
- S4: bottom sheet로 축소, 수량 입력 포함, 조건부 근거 갱신 경로
- S5: 관심종목 상세로 재정의, 가격 3단 표시, `매도 검토` 제거
- (#134) S5 헤더가 `3개월 후`일 때 타이틀 아래 한 줄로 선언 — 로딩에도 서고, 못 찾음에는 없다. S4는 선언하지 않는다
- (#132) 가격 흐름 세 번째 행의 `현재 | 오늘` 중복을 걷어내고 라벨을 `오늘` 하나로 — 날짜 칸은 비운다. `3개월 후` 모드에서도 `오늘`이라고 쓴다
- (#127) S5 상단을 `가격 흐름` 표로 재구성 — 시점을 행으로 세우고, 점선 아래에 파생값을 둔다. 영역 이름이 `가격 정보` → `가격 흐름`, 화면 문구가 `근거 대비` → `담은 날 대비`로 바뀌었다(코드·CONTEXT.md가 줄곧 쓰던 이름이다)
- (#143) S4를 "입력된 전제를 확인하는 자리"로 좁힘 — 수량 입력·합계 삭제(뒤의 실제 주문 화면 몫), `달라짐`이면 근거 요약 대신 깨진 전제를 세움, 근거 없는 종목과 S5 `구매`는 S4 없이 안내 토스트
- (#105) S5 보유중에 `판매`/`구매` 대칭 배치 — 위 `매도 검토` 제거 결정을 ADR-0009가 대체. 두 상태가 같은 골격(근거 갱신은 body 맨 아래, 하단 바는 왼쪽만 갈림)을 쓰도록 정리
- 카테고리별 후속 질문 7종 전체 정의
