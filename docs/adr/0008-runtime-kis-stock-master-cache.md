# 종목 마스터를 런타임에 내려받아 인메모리 캐시한다

검색(S1.5)을 데모 화이트리스트 27종에서 상장 종목 전체로 넓히면서, 종목 목록의 출처가
필요해졌다. **KIS OpenAPI에는 이름으로 종목을 찾는 엔드포인트가 없다** — `CTPF1002R`
(주식기본조회)는 종목코드를 받아 이름을 돌려주는 단방향이라 "삼성전자"로 005930을 얻는 경로가
없다. 대신 KIS가 인증 없이 공개 배포하고 매일 갱신하는 종목 마스터 파일
(`kospi_code.mst.zip` / `kosdaq_code.mst.zip`)을 서버에서 내려받아 파싱하고, 12시간 TTL
인메모리 캐시에 둔다. 자매 프로젝트 `investmentdiary`(#18)에 검증된 구현이 있어 파서·랭킹·
테스트를 그대로 옮긴다.

## Considered Options

**빌드타임 스냅샷** — 같은 파서를 `scripts/`에 두고 결과를 `.generated.json`(약 2,600행)으로
커밋하는 안. 검색이 클라이언트 동기 필터로 남아 즉시 반응한다는 장점이 있었으나, 신규 상장
종목이 스크립트를 다시 돌릴 때까지 검색되지 않는다. 자동 갱신을 공짜로 얻는 쪽을 택했다.

**DB 테이블** — drizzle 스키마에 `stocks`를 추가하는 안. 마이그레이션·시드 유지 비용에 비해
얻는 것이 없어 버렸다.

## Consequences

**#59와 정면으로 보이는 지점을 남긴다.** 이 레포는 KIS 토큰 캐시가 서버리스 인스턴스
메모리에만 있어 배포 환경에서 간헐적으로 실패한 적이 있고(#59), 그래서 토큰은 DB로 옮겼다.
여기서 다시 인메모리 캐시를 고르는 이유는 **실패의 성격이 다르기 때문이다**: 토큰은 캐시가
비면 인증 자체가 깨졌지만, 마스터는 콜드스타트에서 220KB를 다시 받는 비용일 뿐이고 다운로드가
실패해도 빈 배열로 접힌다. 이 문단이 없으면 다음 사람이 "또 인메모리네"라고 되돌리려 할 것이다.

**마스터를 종목 존재의 심판자로 쓰지 않는다.** 마스터 조회가 실패하면 빈 배열이 되므로,
라우트가 조회 결과로 `notFound()`를 결정하면 다운로드 실패 한 번에 모든 종목이 404가
된다. 라우트 가드는 `isTickerShaped` 형식 검증으로 낮추고, 존재하지 않는 종목은 S3의 KIS
시세 조회(`quote-unavailable`)가 걸러낸다 — 네트워크 실패를 "그런 종목 없음"으로 둔갑시키지
않는다(#79·#81과 같은 계보).

**티커는 6자리 숫자가 아니다.** 처음에 가드를 `/^\d{6}$/`로 썼는데, 실 마스터를 받아보니
2,720종 중 **79종이 영문자를 포함**했다 — 신형 우선주 코드(`00088K` 한화3우B, `02826K`
삼성물산우B)와 신규 상장(`0126Z0` 삼성에피스홀딩스, `0001A0` 덕양에너젠)이다. 그대로
나갔다면 그 79종이 전부 404가 됐다. 길이는 언제나 6이다(실측 2,720종 전부).

**실측(2026-08-27).** KOSPI 916종 + KOSDAQ 1,804종 = **2,720종**. ETF·리츠·ETN은
그룹코드 `ST` 필터에서 걸러진다(KODEX 200 부재 확인). KOSDAQ 트레일러 222가 맞다는 것도
에코프로비엠이 정상 파싱되는 것으로 확인했다.

**마스터는 종목코드와 이름만 준다.** 업종이 없으므로 `Stock.sector`가 optional이 되고, 없으면
LLM 프롬프트에서 그 자리를 통째로 뺀다. 큐레이션된 업종 라벨은 데모 화이트리스트 27종에만
남는다.
