# 사기 전에 - 왜 담았는지 기억하기

관심종목에 종목을 담을 때 "왜 담는지"를 묻고, AI가 그 이유를 함께 짚어봅니다.
나중에 실제로 살 때는 다시 묻지 않고 그때 적어둔 내용을 보여주고,
적어둔 전제가 깨지면 사용자에게 알려줍니다.

## 왜 만들었나

매매일지나 투자원칙을 기록하는 앱은 이미 많습니다. 그런데 대부분 자리를 잡지 못했습니다.

그 이유는 기록이 거래와 분리되어 있기 때문이라고 생각합니다. 
별도의 앱에 손으로 옮겨 적어야 하는 기록은 정작 매수하는 순간에 열리지 않고, 열리지 않은 기록은 검증될 수도, 투자한 이유와 전제가 무너졌을 때 알아챌 수도 없습니다.

그래서 기록하는 자리를 **관심종목에 담는 순간**으로 옮겼습니다. 
아직 살지 말지 정하지 않은 상태라 시간 압박이 없고, 무엇보다 주문 흐름을 건드리지 않습니다.



## 어떻게 동작하나

| | 언제 | 무엇을 |
|---|---|---|
| **1** | 관심종목에 담을 때 | "왜 이 종목이 궁금하세요?"를 묻습니다. 카테고리를 고르고, 이어지는 질문에 답하고, 원하면 한두 줄 덧붙입니다 |
| **2** | 담기 직전 | AI가 반대 시각과 확인해볼 질문을 보여줍니다. 반박할 지점이 약하면 억지로 만들지 않습니다 |
| **3** | 저장할 때 | 적은 내용을 나중에 확인 가능한 형태로 분해합니다. 예) "PER 15배 아래를 유지한다" |
| **4** | 실제로 살 때 | 새로 묻지 않고 그때 적은 내용을 보여줍니다. 적어둔 게 없으면 아무 일도 일어나지 않습니다 |
| **5** | 담아둔 동안 · 보유하는 동안 | 저장한 전제가 깨지면 알려줍니다 |

## 시작하기

```bash
bun install
cp .env.example .env.local   # 값을 채운 뒤
bun dev
```



## 설계 노트

**AI는 종목을 추천하지 않습니다.**
"사세요", "좋은 종목입니다" 같은 판단을 내리지 않고, 사용자가 이미 적은 이유를 검토하기만 합니다. 판단의 주체가 끝까지 사용자에게 남습니다.

**주문 흐름에 마찰을 걸지 않습니다.**
매수 버튼과 체결 사이에 입력을 요구하면 체결 가격이 밀립니다. 사용자에게 그건 불편이 아니라 손해입니다. 개입은 관심종목 단계에서만 일어나고, 이유를 적지 않은 종목에는 아무 일도 생기지 않습니다.

**자동으로 확인할 수 없는 전제는 그렇다고 표시합니다.**
"경쟁사가 진입하지 않는다" 같은 전제는 수치로 판정할 수 없습니다. 감추지 않고 `직접 확인 필요`로 구분해 보여줍니다.



## 주의

- 개인 프로젝트이며 **투자 자문이 아닙니다.** 모든 정보는 기록과 점검을 돕기 위한 것이고, 투자 판단과 책임은 사용자에게 있습니다.
- 시세·재무 조회에 쓰는 키는 **조회 전용**으로, 주문 권한이 없는 경로에서만 사용됩니다.
